# A7 GPU (G3): what is known, what the probe does, what comes next

The A7 (S5L8960X) has a PowerVR G6430, Apple's "G3". No Orchard code drove
it before this change. The J85 field report ([j85.md](../j85.md)) got as
far as one framework-owned GFX power transition on a private RAM image.
This page lists what Apple's own data says about the GPU, what the first
driver step does, and what is still unknown. Every value below comes from
Apple's restore images for the boards' own recipes (iOS 12.5.8, 16H88:
J71, J85 and N51; iOS 12.5.7, 16H81: J72) or from this repository. Nothing
else is assumed.

## From Apple's images

| What | Value | Where |
|---|---|---|
| ADT node | `arm-io/sgx`, `compatible = "gpu,s5l8960x"` | J71, J85, N51 device trees (identical) |

| Fender | `0x2_01e00000`, `0x100000` | `sgx` `reg[1]` (the A8's and A9's addresses) |
| Interrupts | AIC 84, 85, 86, 87, 88 | `sgx` `interrupts` |
| Firmware's interrupt | AIC 88: the second `meta-sw-interrupt` tuple (`0x20e104008`, mask `0x1000000`), as AIC 138 is on the A8 | `sgx` `meta-sw-interrupt` |

## What the kernel does now

- `apple,s5l8960x-gpu` in the `apple,s8003-gpu` binding, with the A9's
  node shape: `rgx`, `fender`, `power-domains = <&ps_gfx>`, five interrupts.
- The node is in `s5l8960x.dtsi`, enabled on every A7 board.
- powervr matches it with `pvr_apple_chip_s5l8960x`
  (`pvr_apple_s5l8960x.c`). That chip stops the probe with `-ENODEV`, so
  the GPU is never bound. By default it touches no GPU register: `ps_gfx`
  goes on when the device attaches and off when the probe fails.
- `powervr.apple_a7_read_id=1` is an experiment. With it, the probe wakes
  Fender into state 1 behind an empty boot stream, as the A8 does before
  its ID read, then logs `CORE_REVISION` and `CORE_ID` and puts Fender back
  to state 0. The A8 has no PLL check for this step, and on the A8 a Rogue
  access with the PLL unlocked hung the SoC. **This read may hang the
  iPad.**
- Every A7 recipe installs `lib/firmware/apple/gfx-s5l8960x.bin`, Apple's
  LDR byte for byte, from the J85 16H88 kernelcache (pinned, as the A8
  boards pin N102's). Nothing loads it yet.

## Unknown, needed before the firmware can boot

1. `CORE_REVISION` and `CORE_ID`, which powervr's BVNC needs. The first
   hardware test reads them. Imagination lists G6430 as BVNC 1.72.4.12 on
   Intel Moorefield. Apple's core may differ.
2. The GPU's PLL and its lock bit in the A7 PMGR. The A8 uses `PLL5`
   (`0x5004`, bit 30), but nothing shows that the A7 uses the same one.
3. The A8's global enables (`MISC_ACG 0x32000`, `SOC_TVM 0x2d000`,
   `VM_CTL 0x23000`) and its GPU performance records (`0x1c000`): do they
   exist on the A7, and where?
4. The bridge settings for bridges 11 and 12. They are zero in the restore
   ADT, so they have to be read from the live ADT that m1n1 receives
   (`orchard.apple.adt_capture`).
5. The firmware's segment layout, init data and object offsets, the
   equivalents of the `T7000_*` constants. They have to be read from
   `AGXG3` in the 16H88 kernelcache, as the A8's were read from `AGXG4P`.
6. Whether the border-colour-table candidate is that table on the A7.
